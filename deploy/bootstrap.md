# runanalyze — Oracle instance bring-up

Documented steps, not a script to run blindly — read each one. Exposure
model: Tailscale (no inbound ports opened anywhere). Service user:
`runanalyze`. No real secrets appear anywhere below; every credential is
placed by hand.

**This is documentation only — do not deploy from this session.** Nothing
here has been run against a real instance.

## 1. OS packages

```bash
sudo apt update
sudo apt install -y build-essential libffi-dev libssl-dev python3-dev \
  python3-venv git cargo
sudo timedatectl set-timezone <Region/City>   # match your own timezone, not UTC
```

## 2. Dedicated service user

```bash
sudo useradd -m -s /bin/bash runanalyze
sudo -u runanalyze -i
```
Everything below this point runs as `runanalyze` unless noted.

## 3. Tailscale (exposure model)

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up            # one-time interactive auth
sudo tailscale serve --bg 443 http://127.0.0.1:8000
```
`tailscale serve` terminates TLS and proxies to the app on loopback — the
app itself never binds anywhere but `127.0.0.1`. No VCN security-list rule
is added for it; only the pre-existing SSH (22) ingress rule should exist.
Verify after bring-up:
```bash
ss -tlnp | grep 8000          # must show 127.0.0.1:8000, not 0.0.0.0
sudo iptables -L -n | grep 8000   # must show nothing
```

## 4. Git clone

```bash
git clone <repo-url> /home/runanalyze/runanalyze
cd /home/runanalyze/runanalyze
```
(If publishing to GitHub is kept — see README's publishing note — this
needs a write-capable SSH deploy key and `known_hosts` entry instead of
HTTPS; not required for the web dashboard itself to function.)

## 5. Python environment

```bash
python3 -m venv /home/runanalyze/runanalyze/.venv
source /home/runanalyze/runanalyze/.venv/bin/activate
pip install -r requirements.txt
pip install garmindb
```
Watch for anything compiling from source (e.g. `cryptography`) — expected
to resolve to a wheel on aarch64, but confirm rather than assume.

## 6. Secrets — placed by hand, never generated by any tool

```bash
cp .env.example .env
chmod 600 .env
```
Fill in `.env`:
- `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL` (optional `DEEPSEEK_VISION_MODEL`)
- `DASHBOARD_USER` (display only)
- `DASHBOARD_PASSWORD_HASH` — generate with:
  ```bash
  .venv/bin/python webapp/scripts/hash_password.py
  ```
  Paste the printed argon2id hash into `.env`. The plaintext password is
  never written anywhere by this script.
- `SESSION_SECRET_KEY` — generate with:
  ```bash
  python -c "import secrets; print(secrets.token_hex(32))"
  ```
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — same bot/chat as the acuity
  project if you want alerts in the same place; separate bot is fine too.

Garmin credentials are **not** set here — they're entered once through the
dashboard's Garmin connection panel after the app is running (see step 9).
If you'd rather seed them by hand instead: copy
`~/.venv/lib/*/site-packages/garmindb/GarminConnectConfig.json.example` (or
use the schema documented in `webapp/garmin_config.py`) to
`~/.GarminDb/GarminConnectConfig.json`, fill in `credentials.user` /
`credentials.password`, then `chmod 600` it.

## 7. systemd units

```bash
sudo cp deploy/systemd/*.service deploy/systemd/*.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now runanalyze-web.service
sudo systemctl enable --now runanalyze.timer
```
Do **not** enable `runanalyze.service` directly — it's triggered by the
timer (and by the web app's refresh button), not meant to run standalone.

## 8. Verify

```bash
systemctl status runanalyze-web.service
systemctl list-timers | grep runanalyze
journalctl -u runanalyze-web -f
```
From a device on your tailnet: open `https://<instance>.<tailnet>.ts.net/`,
confirm the login page loads, and that a device NOT on your tailnet cannot
reach it at all.

## 9. First-time Garmin login (do this before trusting the nightly timer)

1. Log into the dashboard, go to the Admin tab, enter your Garmin Connect
   email + password in the connection panel, save.
2. SSH in and run the sync once interactively, to catch an MFA prompt if
   your account has one enabled (see CLAUDE.md's MFA decision — option 1,
   MFA disabled on this account, was chosen; if that changes, a fresh
   login will need this manual step every time the cached session dies):
   ```bash
   .venv/bin/python -m garmindb_cli --activities --download --import --analyze --latest
   ```
3. Confirm `~/.GarminDb/garth_session` now exists and the Admin tab's
   Garmin status shows "Connected".

## 10. Co-tenancy note

If acuity is ever deployed to this same instance, give it its own
dedicated service user — never share `runanalyze`'s account. See the
recon conversation's co-tenancy section for why (the `ProtectHome=tmpfs`
+ `BindPaths` hardening above is scoped to this account's home only).
TradingAgent is out of scope for this box (Docker-only, conflicts with
"no containers").
